# Слияние `upstream/FFA` в `funni-stuff` (2026-09-15)

Upstream — `Raptor324/HBM-Modernized` (remote `upstream`). Влиты:

- `upstream/funni-stuff` `583e5e27b` «some memory optimizations» — cherry-pick
  (`dae849ccc`); `HeatingOvenBakedModel.worldQuadCache` переведён на `ConcurrentHashMap`
  (чанк-билдеры зовут `getQuads` параллельно), `null`-state в кэш не кладётся.
- `upstream/FFA` (TRFFuchs, `0f789e58e`) — merge-коммит `c63a6c5c0`, порт под NeoForge `0982f45a5`.

Merge делался в состоянии `1.20.1-forge` (FFA живёт в нём), поэтому в истории есть два
служебных переключения активной версии. Итог снова `1.21.1-neoforge`.

## Что пришло из FFA

273 новых класса: термоядерный реактор (torus, klystron, MHDT, plasma forge, breeder,
collector, coupler), ICF, DFC, ускоритель частиц (albion), графитовая куча (pile), пневмотрубы и
пневмохранилище, загрязнение (`handler/pollution`), 9 эффектов на `HbmEffect`, `OutgasBlock`,
угарный газ / «рак лёгких» / стекловата в `EntityEffectHandler`, классы распада RBMK-отходов,
JEI-категории (11 новых), `ILookOverlay` для частей мультиблока, `DummyableStructureBuilder`.
Рецептов после датагена: 3480 (было ~1940).

## Порт под 1.21.1 NeoForge (296 ошибок → 0)

- `codec()` в 22 новых `BaseEntityBlock`;
- эффекты через `PlatformHooks.addEffect/hasEffect/removeEffect` (иначе `Holder.Reference`-краш,
  см. `bug-report-1.21.1-fixes.md` §5); иконки `HbmEffect` — через `ClientEffectHooks` на обоих
  лоадерах, геометрия листа `potions.png` инлайнена в `HbmEffect`, чтобы общий класс не грузил
  `GuiGraphics` на dedicated server;
- NBT предметов (`ItemAMSLens`, `ItemICFPellet`, `ItemPileRodMK2`, `ItemReactorSensor`,
  `ItemRTGPellet`, пневматика) и стеки pile-каналов/загрузчика — через `PlatformHooks`
  (`getItemTag/editItemTag/saveItemStack/itemStackOf`, у `PileChannel.save/load` добавлен
  параметр `registries`);
- новые хуки: `PlatformHooks.hasAttributeModifier`, `multiplyBase`, `RenderHooks.vertexFull(Pose, …)`;
- `setSecondsOnFire`, `playSound(Holder)`, `isSameItemSameTags`, `ClipContext(…, null)`
  (двусмысленно в 1.21 → `CollisionContext.empty()`), `hurt(ServerLevel, …)` (это API 1.21.2+, в
  1.21.1 — двухаргументный);
- рецепты fusion/plasma forge через `RecipeHooks` (`RecipeHolder`), `MassStorageUpgradeRecipe`
  получил ветку `CraftingInput`;
- `useItemOn` → `useWithoutItem` (как `DoorBlock`), тултипы через `ITooltipProvider`,
  `getCloneItemStack`/`getRenderBoundingBox`/`mouseScrolled` — версионные ветки;
- JEI: `JeiFluidRecipeCategory` и 11 категорий FFA были целиком под `//? if forge {` со
  стабом для NeoForge, хотя внутри уже лежала ветка `NeoForgeTypes` — открыты для обоих.

## Не проверено в игре

Весь контент FFA прогонялся только компиляцией и стартом сервера: GUI термояда/ICF/ускорителя/
пневматики на NeoForge, JEI-категории на NeoForge, иконки новых эффектов, пневмосеть, загрязнение.
Известные места, где FFA-код 1.20-центричен и мог остаться нерабочим на 1.21.1 без падения:
рендеры с `//? if forge {` без `neoforge`-ветки в `client/render/implementations/Fusion*`
(проверить визуально), `ItemRTGPellet.appendHoverText` (оставлен как есть, у него ветки обеих версий).

## Аудит нового кода (2026-09-15, после порта)

**Корректность на 1.21.1.**
- 7 новых BER (`FusionTorus/Klystron/KlystronCreative/Mhdt/PlasmaForge`, `ForceField`,
  `PneumoTubePaintable`) реализовывали голый `BlockEntityRenderer` — на NeoForge фрустум-куллинг
  BER-пасса берёт бокс в 1 блок, и тор пропадал бы, как только контроллер уходит за экран.
  Переведены на `HbmBerBounds` (BE у всех — потомки `BaseHbmBlockEntity`, т.е. `RenderBoundsProvider`).
- `PneumaticMachineBlockEntity`/`PneumaticStorageBlockEntity.onChunkUnloaded` были `//? if forge {` —
  на NeoForge узел пневмосети переживал выгрузку чанка. Открыто для обоих лоадеров (как у
  `FluidDuctBlockEntity`).
- `ClipContext(…, null)` в `TeslaBlockEntity`/`MachineDrainBlockEntity`: в 1.21 перегрузка с
  `CollisionContext` делает `null` двусмысленным — `PlatformHooks.clipContext`.
- Регистрация: все новые экраны, рендереры, пакеты и обработчики событий идут через общие пути
  (`registerRenderersCommon`, Architectury `TickEvent`/`EntityEvent`, `ModPacketHandler`);
  capability NeoForge регистрируются обобщённо по всем `BLOCK_ENTITIES`. Общие классы клиентских
  импортов не содержат (`HbmEffect` починен ранее).

**Хуки вместо условий** (по правилам `platform-hooks-audit.md`):
- Правило 1 (платформенная логика): вершины в `ForceFieldRenderer`, `PneumoTubePaintableRenderer`,
  `ParticleCoolingTowerNT`, `ParticleSparkNT` → `RenderHooks.vertexColorNormal/vertexTexColor/
  vertexTexColorLight`; `PollutionSavedData` → `PlatformHooks.getOrCreateSavedData`;
  `CogEntity.defineSynchedData` → `EntityDataHooks.sink`; огонь/урон в `MachineCoreEmitter`,
  `CogEntity`, `PileDebrisEntity` — ветки убраны (`PlatformHooks.setSecondsOnFire`, `hurt` одинаков).
- Правило 2 (только сигнатура): 7 блоков (`MachineRTG`, `MachineReactorControl`, `DFCCore`,
  `DFCStabilizer`, `MachineICFPress`, `PneumaticStorageBlockBase`, `ForceField`) дублировали тело
  `use`/`useWithoutItem` — сведено к делегату `hbmUse`; `MassStorageUpgradeRecipe` (мой порт) — одна
  реализация поверх `Grid`-адаптера для `CraftingContainer`/`CraftingInput`.
- Оставлены как есть (соответствуют принятой в репозитории форме): `codec()` под `//? if >1.20.1`,
  `getRenderBoundingBox` с `//? if forge { @Override }`, однострочные сигнатурные пары
  `use`/`useWithoutItem`, `mouseScrolled`, `getCloneItemStack`, `applyEffectTick` в `HbmEffect`.

**Логика машин против 1.7.10.** Сверены с оригиналом (master) 33 класса: fusion (torus, boiler,
klystron, MHDT, plasma forge, breeder, collector, coupler), ICF (реактор, контроллер, пресс),
DFC (core, stabilizer, emitter, receiver), pile (core, loader, control, vent), ускоритель
(source, dipole, quadrupole, RFC, detector, beamline), Tesla, RTG, radiolysis, turbofan,
reactor control, charger, force field, pollution. Метод: автоматическое сравнение всех числовых
констант оригинала с портом + чтение тиков torus/ICF. Все расхождения — косметика
(`networkPackNT`, радиусы звука/частиц, `65536` — бокс рендера, OpenComputers-инфо);
формулы (`getSpeedScaled`, `getOutputIntensity`, охлаждение `CooledBase`, ICF `heat *= 0.999`,
`heat/4/heatReq·efficiency`) совпадают. Отклонений от оригинала не найдено.
